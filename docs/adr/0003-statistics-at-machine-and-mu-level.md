# Statistics at two levels: machine state and MU time

Every material-flow object keeps two sets of time statistics. Machine-level buckets give each moment to exactly one state, by a fixed priority where failed beats paused and a stop beats everything else, because the time bases and availability need them. MU time records what each MU in the object is doing, because machine-level time alone hides what's happening in a multi-MU object: a capacity 2 Station with one slot working and the other holding a blocked MU looks 100% busy and never blocked, which points a utilisation ranking at the wrong place. So utilisation and bottlenecks are judged from MU time, and no bottleneck figure is stored. We rejected the active-period method, even though it needs only one more counter, because "active" isn't well defined for a partly blocked multi-MU object.
